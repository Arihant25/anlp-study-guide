Lecture 11 · 25 slides

Speculative Decoding: guess cheaply, check in parallel.

A language model writes one token per forward pass, and each pass through a large model is slow. This lecture has two parts. The first is min-p sampling, a way to choose which tokens are allowed when sampling. The second is speculative decoding: a small draft model guesses several tokens ahead, the large model checks all of them in a single pass, and a careful accept/reject rule makes the result follow exactly the distribution the large model would have produced on its own.

§1Why decoding is slow

A model that generates text writes one token, appends it to the input, and runs again. Every new token costs a full forward pass through the whole model, and the passes cannot overlap, because each one needs the previous output.

Slide 01 / 25
slide 01 · title

On the slide

The title is "Decoding & Generation", the same theme as Lecture 10. The course site lists this lecture as "Speculative Decoding" (the PDF is named ANLP-M26-Advanced_Decoding.pdf), because that is its main new topic.

Where this fits

Lecture 10 covered how to pick the next token from the model's probability distribution: greedy, beam search, temperature, top-k, top-p. This lecture adds one more way to pick (min-p) and then changes the question. Speculative decoding does not change what the model generates. It changes how fast it is generated.

Slide 02 / 25
slide 02 · one token per model call

On the slide

"Once upon" goes in, "a" comes out. "Once upon a" goes in, "time" comes out. "Once upon a time" goes in, "there" comes out. Each output token is fed back as part of the next input.

Why it has to be sequential

The model defines the probability of a sequence as a product of next-token probabilities, P(x1, …, xT) = ∏ P(xt | x<t). To sample token t you need tokens 1 to t−1 already fixed. So generating 100 tokens means 100 forward passes, one after another. A GPU can do a great deal of work in parallel, but it cannot start pass 2 before pass 1 has finished.

Slide 03 / 25
slide 03 · the loop written as an algorithm

On the slide

The same loop as slide 2, from the survey by Xia et al. (2024):

  • Mq is the language model. x1, …, xt is the prompt, and T is the length to stop at.
  • Line 3: run the model on everything so far, x<n+1, to get qn+1, a probability distribution over the whole vocabulary for the next position.
  • Line 4: draw one token from it. This is where greedy, top-k, top-p or min-p would plug in.
  • Line 5: move one position forward and repeat.

The loop body runs T − t times, and each run is one full forward pass.

⚠ Notation

Here the letter q belongs to the model we actually want to sample from. In slide 19 (Leviathan et al.) q is the small draft model and p is the large target. In slide 25 (Chen et al.) it flips again: q is the target and p is the draft. Always check which letter is which before reading a formula.

Slide 04 / 25
slide 04 · the limitation: it is slow

On the slide

One bullet: inference from large autoregressive models is slow.

Why it is slow, more precisely

The time per token is not mostly spent on arithmetic. When you generate for one user, each forward pass processes a single new token, but it still has to read every weight of the model from GPU memory. A 70B-parameter model in 16-bit precision is about 140 GB of weights. Reading that much memory takes far longer than doing the matrix-vector products with it, so the GPU's compute units sit mostly idle. This is called being memory-bandwidth bound.

✦ Key takeaway

Since the cost of a pass is dominated by reading the weights, running the model on 5 tokens at once costs about the same time as running it on 1 token. The weights are read once either way. Speculative decoding is built entirely on this fact: if we had good guesses for the next few tokens, the big model could check all of them for roughly the price of one step.

Slide 05 / 25
slide 05 · the menu for this lecture

On the slide

Five strategies. They fall into two groups:

  • Choosing better tokens: min-p sampling. It changes the output, not the speed.
  • Generating the same tokens faster: speculative decoding, speculative sampling, Lookahead Decoding and Medusa. All four produce more than one token per pass of the big model.

The two the deck does not cover

Both are alternatives to having a separate draft model. One line each, for orientation only:

  • Medusa (Cai et al., 2024) adds a few extra output heads to the target model itself. Head k predicts the token k positions ahead. Their guesses are then verified by the same model in one pass, using a tree of candidate continuations.
  • Lookahead Decoding (Fu et al., 2024) also uses no draft model. It guesses several future tokens with a fixed-point (Jacobi) iteration, collects n-grams from those guesses, and verifies promising n-grams with the target model.

§2Min-p sampling

Top-p and top-k cut off the unlikely tail of the distribution before sampling. Min-p does the same, but sets the cut-off relative to the most likely token, so the cut-off moves with how confident the model is.

slide 06 · section divider

On the slide

Section title only.

Slide 07 / 25
slide 07 · a threshold that moves with confidence

On the slide

Min-p sets its sampling threshold separately at every step, based on how confident the model is at that step. The claim is that this balances creativity and coherence better, especially at high temperature. The source is Nguyen et al., ICLR 2025.

The problem it is aimed at

Raising the temperature τ divides the logits by τ before the softmax, which flattens the distribution. That makes text more varied, but it also gives more probability to junk tokens far down the tail. Top-p keeps the smallest set of tokens whose probabilities add up to p. When the distribution is flat, that set can be very large and include many bad tokens. Min-p is meant to stay strict in that case.

→ Recap

Temperature, top-k and top-p are explained in Lecture 10.

Slide 08 / 25
slide 08 · intuition

On the slide

The threshold is relative. A confident model gets a small pool of candidates; an unsure model gets a larger one. ("Intution" on the slide is a typo for "intuition".)

Why "relative" is the key word

Top-k uses a fixed count and top-p a fixed amount of probability mass. Neither looks at how peaked the distribution is. Min-p's threshold is a fraction of the top token's probability, so a high peak means a high bar and a flat distribution means a low bar. The next slide gives an example of each case, and slide 10 gives the formula.

Slide 09 / 25
slide 09 · low-certainty vs high-certainty prompts

On the slide

Two prompts. After "The battle that ensued", many continuations are fine: "was", "lasted", "raged", "left". After "refraction, reflection, and dispersion of", the answer is almost certainly "light".

Putting numbers on it

Use a base threshold pbase = 0.1.

  • Rainbow: say P(light) = 0.85, then 0.06, 0.05, 0.04 for the next three. The threshold is 0.1 × 0.85 = 0.085, so only "light" survives. Top-p with p = 0.9 would keep two tokens (0.85 + 0.06 = 0.91 ≥ 0.9), letting in a 6% option for no reason.
  • Battle: say the top token has 0.12 and the probabilities fall off slowly. The threshold is 0.1 × 0.12 = 0.012, so every token above 1.2% stays in the pool, and there could be dozens.
Slide 10 / 25
slide 10 · the algorithm in four steps

On the slide

Four steps:

pmax= maxv∈𝒱 P(v∣x1:t−1) pscaled= pbase×pmax 𝒱min= {v∈𝒱: P(v∣x1:t−1) ≥pscaled} P′(v)= P(v∣x1:t−1) ∑v′∈𝒱min P(v′∣x1:t−1) for v∈𝒱min

Reading it

  • 𝒱 is the vocabulary. P(v | x1:t−1) is the model's probability for token v given everything so far.
  • pbase is the one hyperparameter. Values around 0.05–0.1 are common. pbase = 1 keeps only the top token (greedy, ignoring ties). Smaller values keep more tokens.
  • 𝒱min is the pool of tokens that pass. The top token always passes, because pmax ≥ pbase · pmax, so the pool is never empty.
  • The last line renormalises: divide each surviving probability by their total so they sum to 1, then sample.

Small example

Probabilities (0.5, 0.3, 0.15, 0.05) and pbase = 0.2. Then pscaled = 0.2 × 0.5 = 0.1. The first three tokens pass and the last one (0.05) is dropped. The survivors sum to 0.95, so the new probabilities are 0.5/0.95 ≈ 0.526, 0.3/0.95 ≈ 0.316 and 0.15/0.95 ≈ 0.158.

Under the hood

The cost is one max, one comparison per token, and a renormalisation, all of which are cheap next to the forward pass. Top-p needs the probabilities sorted to compute a cumulative sum; min-p does not. Where temperature is applied relative to the min-p filter differs between libraries, and it changes the result, so check the order in the one you use.

That shows min-p avoids producing broken output, which is why the other methods drop to near 0% (they fail to produce a usable answer at all). It does not show that min-p reasons well at τ = 3. The GSM8K columns, where chance is near 0%, are the more telling comparison.

§3A short history of draft-then-verify

The rest of the lecture is about speed. Before the method itself, one slide shows where it came from.

Slide 14 / 25
slide 14 · from blockwise decoding (2018) to Medusa (2023)

On the slide

A timeline from the Xia et al. survey. The main milestones:

  • 2018, Blockwise Decoding (Stern et al.): the first draft-then-verify method. Extra heads on the model propose several tokens and the model checks them. This is an ancestor of Medusa.
  • 2022.03, Speculative Decoding (Xia et al.): introduces the name, with a separate non-autoregressive drafter.
  • 2022.11, Speculative Decoding (Leviathan et al., Google): uses an ordinary small language model as the drafter and adds an accept/reject rule that works for sampling, not only for greedy decoding. This is the algorithm on slide 19.
  • 2023.02, Speculative Sampling (Chen et al., DeepMind): the same idea, found independently and applied to a 70B model. This is slides 24–25.
  • 2023 onwards: many variants. Hugging Face's "Assistant Generation" put it into the transformers library; SpecInfer and SpecTr verify trees or sets of drafts; Medusa removes the separate draft model.

Logos on the slide mark the institutions: Google, UC Berkeley, Microsoft, Peking University, DeepMind, Hugging Face, Stanford, Princeton and others.

§4Speculative decoding: the idea

Many tokens are easy enough that a small model would predict the same thing as a large one. Let the small model guess them, and use the large model only to check.

Slide 15 / 25
slide 15 · section divider

On the slide

Section title only.

Slide 16 / 25
slide 16 · a target model and a draft model

On the slide

Two models. The target is the large model whose output we want. The draft is a much smaller model, typically from the same family and with the same tokenizer, that guesses several tokens ahead. The promised speed-up is 2–3×.

What "in parallel" means here

The two models do not run at the same moment on the same token. They take turns. The draft runs γ times in a row (fast, because it is small) to propose γ tokens. Then the target runs once on all γ proposals together. The "parallel" part is that the target scores γ positions in parallel inside a single forward pass.

⚠ Watch out

The draft and target must share a vocabulary, because the target is asked "what is your probability for this token?" about the draft's tokens. That is why drafts are usually small members of the same model family.

Slide 17 / 25
slide 17 · easy tokens and hard tokens

On the slide

After "Geoffrey Hinton did his PhD at the University", the next token "of" is very easy, and a 1B model would get it right. After "…at the University of", the next token "Edinburgh" needs real knowledge, and only the 100B model is likely to get it right.

Why this suggests a speed-up

In ordinary text a large share of tokens are like "of": function words, the second half of a word, the closing of a common phrase. Spending a 100B-parameter forward pass on each of them is wasteful. If a 1B model handles the easy ones, the big model's work is only needed for the hard ones. The difficulty is that we don't know in advance which tokens are easy. The next slide shows how to find out cheaply.

Slide 18 / 25
slide 18 · checking a whole draft in one pass

On the slide

The draft model has proposed "at the University of Toronto" (grey). The 100B model reads the prompt plus the whole draft in one forward pass. It agrees with "at the University of" (green) and disagrees with "Toronto" (red). Hinton's PhD was from Edinburgh, as slide 17 says.

Why one pass is enough to check all of them

This is the same property that makes training efficient. A causal transformer outputs a next-token distribution at every position of its input, not only the last. Fed "Geoffrey Hinton did his PhD at the University of Toronto", the target gives in one pass:

  • its distribution after "…PhD", to check "at",
  • its distribution after "…PhD at", to check "the",
  • and so on up to its distribution after "…University of", to check "Toronto",
  • plus its distribution after "…Toronto", which gives one extra token if everything is accepted.

The first rejected position is where the draft and target part ways. Everything after it is thrown away, because it was conditioned on a wrong token. At the rejected position, the target's own distribution is already available, so it supplies the replacement ("Edinburgh") at no extra cost.

✦ Key takeaway

One target pass now produces between 1 and γ + 1 tokens instead of exactly 1. Because the pass is memory-bound (slide 4), checking γ + 1 positions costs about the same as generating 1.

§5The algorithm

For greedy decoding the rule is simple: keep draft tokens while they equal the target's top choice. For sampling it needs more care, because we want the output to have exactly the target model's distribution. Slide 19 gives the rule that achieves this.

Slide 19 / 25
slide 19 · one step of speculative decoding (Leviathan et al.)

On the slide

Algorithm 1 from Leviathan, Kalman and Matias (ICML 2023). Notation: Mp is the target with distributions p; Mq is the draft with distributions q; γ (gamma) is how many tokens the draft guesses per step.

The four phases

  1. Draft. Run the small model γ times to sample guesses x1, …, xγ, remembering each distribution qi.
  2. Verify. Run the big model once on prefix + all guesses. This yields γ + 1 distributions p1, …, pγ+1, one for each position (slide 18).
  3. Accept or reject. For each guess i, draw a uniform random number ri. Guess i is rejected if ri > pi(xi) / qi(xi). n is the number of guesses accepted before the first rejection (or γ if none is rejected).
  4. Fix up. Sample one more token t from the target. If a guess was rejected, sample from the corrected distribution below. If all were accepted, sample from pγ+1, the free extra position.

The accept/reject rule

The rejection condition r > p/q is the same as accepting with probability

P(accept x)= min(1, p(x)q(x) )

and, after a rejection, sampling the replacement from the residual distribution

p′(x)= max(0,p(x)−q(x)) ∑x′max(0,p(x′)−q(x′))

In words: if the target likes the draft's token at least as much as the draft did (p ≥ q), always keep it. If the draft was over-confident (q > p), keep it only with probability p/q. When you reject, pick a replacement only from tokens the draft under-weighted, in proportion to how much it under-weighted them.

A worked example

A three-word vocabulary. At some position the draft and target give:

  • draft q = (cat 0.6, dog 0.3, fox 0.1)
  • target p = (cat 0.4, dog 0.4, fox 0.2)

Acceptance probabilities. cat: min(1, 0.4/0.6) = 2/3. dog: min(1, 0.4/0.3) = 1. fox: min(1, 0.2/0.1) = 1. Only "cat", which the draft over-weights, can be rejected.

Residual. max(0, p − q) = (0, 0.1, 0.1). It sums to 0.2, so the normalised residual is (cat 0, dog 0.5, fox 0.5).

Check that the output follows p. The probability of a rejection is 0.6 × (1/3) = 0.2. Then:

  • P(cat) = 0.6 × 2/3 + 0.2 × 0 = 0.4
  • P(dog) = 0.3 × 1 + 0.2 × 0.5 = 0.4
  • P(fox) = 0.1 × 1 + 0.2 × 0.5 = 0.2

That is exactly p. The output has the target's distribution even though most tokens came from the draft.

Under the hood: why it always works

For any token x, the chance of drafting it and keeping it is q(x) · min(1, p(x)/q(x)) = min(p(x), q(x)). The chance of a rejection overall is 1 − Σ min(p, q), which equals Σ max(0, p − q), the normaliser of the residual. So the chance of producing x via a rejection is max(0, p(x) − q(x)). Adding the two paths gives min(p, q) + max(0, p − q) = p(x) for every x. This is a form of rejection sampling, and it is why speculative decoding is lossless: the outputs are distributed exactly as if the target had generated them alone.

⚠ Notation on the slide

In the line computing n, "pi(x) / qi(x)" means the probabilities of the specific drafted token, pi(xi) / qi(xi). The x without a subscript is the paper's shorthand. Also, norm(·) means "divide by the sum so it adds up to 1".

The greedy special case

With greedy decoding, both p and q put probability 1 on their top token. The rule then becomes: accept the draft token if it equals the target's argmax, otherwise replace it with the target's argmax. That is exactly the Toronto/Edinburgh picture on slide 18.

Slide 21 / 25
slide 21 · between 1 and γ + 1 tokens per target pass

On the slide

  • Worst case, 1 token: the first guess is rejected, and the target's replacement is the only new token. This is no worse than ordinary decoding in tokens per target pass.
  • Best case, γ + 1 tokens: all γ guesses are accepted, plus the free token from pγ+1.

The average case

The slide gives only the extremes. Leviathan et al. also derive the average. Let α be the acceptance rate, the probability that a single draft token is accepted. Averaged over the draft's choices this is α = Σx min(p(x), q(x)), so it measures how similar the two models are. In the slide 19 example, α = 0.4 + 0.3 + 0.1 = 0.8. Treating each position as an independent trial with the same α, the expected number of tokens per target pass is

E[tokens per pass]= 1+α+α2+⋯+αγ = 1−αγ+1 1−α

Each term is the chance of getting that far: you always get at least 1 token, you get a 2nd if the first guess is accepted (probability α), a 3rd if the first two are accepted (α²), and so on.

Example. α = 0.8, γ = 4: (1 − 0.85) / (1 − 0.8) = (1 − 0.328) / 0.2 ≈ 3.36 tokens per target pass. With α = 0.5 and the same γ: (1 − 0.55) / 0.5 ≈ 1.94.

Under the hood: tokens per pass is not the speed-up

Each step also pays for γ draft passes. If one draft pass costs a fraction c of a target pass, a step costs about γc + 1 target-pass units, so the speed-up is roughly (1 − αγ+1) / ((1 − α)(γc + 1)). With α = 0.8, γ = 4, c = 0.05: 3.36 / 1.2 ≈ 2.8×. Larger γ gives more tokens when the draft is good, but more wasted draft work when it is not, so γ is tuned to α and c.

§6Limitations

The output is guaranteed correct, but the speed-up is not guaranteed. Everything depends on how often the draft agrees with the target.

Slide 23 / 25
slide 23 · limitations

On the slide

Three limitations. Each one lowers the acceptance rate α or raises the cost per step, so each can be read against the speed-up formula under slide 21.

  • A good draft is hard to get. The draft must be much cheaper than the target and still agree with it most of the time, on the same tokenizer. If no small model in the same family exists, you have to train or distil one, and it may agree well on some domains (prose) and badly on others (code, maths, another language).
  • Accuracy drops on longer sequences. Small models handle long contexts less well, so α can fall as the context grows. Also, within one step, guess i is only useful if guesses 1 to i−1 were all accepted, so later guesses are worth less.
  • Verification overhead. When α is low, each step pays for γ draft passes plus a target pass that is slightly heavier than usual, and gets back about one token. That can be slower than plain decoding.
⚠ Another limitation worth knowing

The method relies on the target being memory-bound (slide 4). When a server batches many users' requests together, the GPU is already busy with arithmetic, and verifying extra positions is no longer close to free. The gains from speculative decoding are therefore largest for a single request or a small batch, and shrink at large batch sizes. It also needs memory for the draft model's weights and its own KV cache.

§7Speculative sampling

DeepMind's version of the same idea, published a few months later and found independently. The algorithm is the same up to notation, and the notation is reversed.

Slide 24 / 25
slide 24 · speculative sampling in three steps

On the slide

Three steps from Chen et al. (DeepMind, 2023): draft K tokens, score them with the target, then accept a prefix of them with modified rejection sampling so the output follows the target's distribution. (Step 2 has a small typo: "the model from we wish to sample from" should read "the model we wish to sample from".)

Mapping to the previous section

  • K here is γ on slide 19.
  • Step 1 allows the draft to be "a parallel model", one that proposes all K tokens at once, not only a small autoregressive model.
  • "Recovering the distribution of the target model" is the lossless property proved under slide 19.

The paper used Chinchilla 70B as the target with a much smaller draft model and reported a 2–2.5× speed-up in its distributed setup, in line with the 2–3× on slide 16.

Slide 25 / 25
slide 25 · Algorithm 2 (SpS), with target q and draft p

On the slide

The full loop from Chen et al. In their notation:

accept x~t if r< min(1, q(x~t∣…) p(x~t∣…) ) ,r∼U[0,1] otherwise sample from (q(x∣…)−p(x∣…))+ and stop

It is the same algorithm as slide 19

  • Draft K tokens x̃1, …, x̃K with the small model.
  • One target pass gives K + 1 distributions.
  • Go left to right. Accept each draft token with probability min(1, target/draft). At the first rejection, sample a replacement from the positive part of (target − draft), normalised, and stop.
  • If all K are accepted, sample one bonus token from the target's last distribution.

The subscript + in (·)+ means "keep the positive part", that is max(0, ·), applied to each token separately. The paper defines it to include normalisation, so it is the same residual as slide 19's norm(max(0, p − q)) with the letters swapped.

⚠ Watch out: the letters are swapped

On slide 19 (Leviathan et al.), p is the target and q is the draft. On this slide (Chen et al.), q is the target and p is the draft. Both papers accept with min(1, target/draft) and resample from (target − draft)+. Write the rule in words ("target over draft") and it will be right whichever paper you are reading.

⚠ Loose indexing on the slide

Three details on the slide, copied from the paper, should be read loosely:

  • In the acceptance test, q(x | …) and p(x | …) mean the probabilities of the drafted token x̃t, not of a generic x.
  • The inner loop increases both t and n on each acceptance, so read literally, xn+t would skip positions. The intended meaning is simply "append the accepted token to the sequence".
  • The variable t is used both for the prompt length (x0, …, xt) and for the loop counter. They are different things.

The worked example in this notation

Re-using slide 19's numbers: target q = (0.4, 0.4, 0.2), draft p = (0.6, 0.3, 0.1). Accept "cat" with probability min(1, 0.4/0.6) = 2/3. The residual (q − p)+ = (0, 0.1, 0.1), normalised to (0, 0.5, 0.5). The arithmetic is identical; only the letters changed.

Zoom out. Autoregressive generation takes one forward pass per token, and each pass is slow mostly because it has to read every weight from memory. Min-p sampling is about which tokens to allow: it keeps tokens whose probability is at least a fixed fraction of the top token's, which keeps output usable at high temperature. Speculative decoding and speculative sampling are about speed. A small draft model proposes γ tokens, and the target checks them all in one pass. Each draft token is accepted with probability min(1, target/draft), and the first rejected one is replaced by a sample from the normalised residual max(0, target − draft). That rule makes the output follow exactly the target's distribution, and the number of tokens per target pass is between 1 and γ + 1, about (1 − αγ+1)/(1 − α) on average. For an exam, be able to state the accept/reject rule, show on a small example that it reproduces the target distribution, and say which letter means which model in each paper.
